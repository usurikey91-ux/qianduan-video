# 自媒体对标监控与事实复盘工作台

> 把每条内容变成下一条内容的证据。

这是一个本地优先的自媒体对标监控与作品事实复盘工作台。它帮助内容创作者持续采集对标账号的公开作品数据，用账号自身近期表现建立基线，找出真正异常突出的作品，并把自己的发布结果沉淀为下一次创作可复用的证据。

本项目当前不把 AI 分析、文案改写或自动二创作为核心流程。账号采集、热度判断和事实复盘均可在不配置 AI 模型、不消耗模型 Token 的情况下完成。

## 项目解决什么问题

内容创作者通常会收藏很多对标账号，但仍然面临几个问题：

- 不同账号体量差异很大，单看点赞数无法判断一条作品是否真的超出作者日常水平。
- 平台字段不完整，很多工具会混用公开数据、推测数据和 AI 判断。
- 自己发布后的数据散落在各个平台，难以持续形成复盘记录。
- 采集、筛选和复盘依赖多个工具，登录状态、数据来源和判断规则不透明。

这个工作台把上述过程整理成一条可检查的事实链路：

```mermaid
flowchart LR
    A[添加对标账号] --> B[定时采集近期作品]
    B --> C[建立账号自身中位数基线]
    C --> D[筛选达到入选倍数的作品]
    D --> E[查看作品公开事实]
    E --> F[复盘自己的发布结果]
    F --> G[形成下一条内容的证据]
```

## 与原项目的区别

本仓库从 [niupTang/douyin](https://github.com/niupTang/douyin) 的多平台工具基础上演进而来，但产品重点已经发生变化。

| 原项目侧重点 | 当前工作台侧重点 |
| --- | --- |
| 多平台视频上传与定时发布 | 对标账号持续监控 |
| Cookie、账号与上传脚本 | 账号主页链接直接添加 |
| 发布自动化 | 公开数据采集与热度判断 |
| 面向一次发布动作 | 面向长期内容证据积累 |
| 平台绝对数据 | 同一账号的相对表现 |

仓库中仍保留部分历史上传模块和适配代码，但它们不是当前界面的核心产品能力，也不是本 README 的主要使用路径。

## 核心方法：账号内相对基线法

本项目不把小账号与全网头部账号直接比较，而是让每个账号只和自己的近期作品比较。

1. 采集账号最近若干条作品，默认参考 20 条。
2. 当前作品不会参与自己的基线计算。
3. 使用历史作品公开指标的中位数作为账号日常水平，降低偶发异常值的影响。
4. 计算当前作品相对账号日常水平的倍数。
5. 默认达到 `5x` 才进入“对标作品试水”；低于门槛不进入，也不再区分“火”和“特别火”。
6. 参考作品数、入选倍数和巡检频率均可在页面中调整。

规则边界：

- 参考作品数可设置为 `5–50` 条。
- 历史样本少于 5 条时不强行判断。
- 历史样本达到 5 条但不足目标数量时，按实际样本计算，并显示 `实际样本/目标样本`。
- 平台没有返回的字段保持为空，不使用推测值补齐。
- 公开指标不足以形成有效基线时，明确显示数据不足。
- 采集和判定过程不调用 AI。

## 当前核心能力

### 1. 对标账号管理

- 粘贴账号主页链接或稳定账号 ID 添加对标。
- 当前重点支持抖音、小红书、B站和快手。
- 自动识别并保存平台昵称，也可以双击昵称自定义修改。
- 每个账号可以暂停或恢复自动监控。
- 彻底删除账号时，同时删除其作品、数据快照和热度记录。

### 2. 可配置的自动巡检

- 全局设置参考作品数、入选倍数和巡检频率。
- 单个账号可以沿用全局设置，也可以单独覆盖。
- 保存规则后立即使用已有数据重算；数据不足时在下一次巡检继续补采。
- 默认巡检规则为：近 20 条、入选 `5x`、每 4 小时。

### 3. 爆款事实筛选

- 只展示平台公开指标、原作品链接和相对倍数。
- 显示参与判断的实际样本数量。
- 不自动生成爆款原因、二创文案或改写脚本。
- 早期公开数据可用于候选筛选，满足最终观察窗口后可再次复核。

### 4. 自有作品事实复盘

- 抖音与小红书作品分别保存和展示。
- 支持平台连接器同步，也支持导入官方 CSV/XLSX 数据文件。
- 根据实际取得的字段展示播放、点赞、收藏、评论、分享、完播率、跳出率和涨粉等指标。
- 页面计算作品数量、中位表现、最高表现、中位互动数和最高作品。
- 支持选择多条作品进行字段对比，不调用 AI 给出主观结论。

### 5. 视频解析

- 视频解析引擎已随工作台打包，启动 5174（由 5409 后端管理）即可使用，不需要额外启动 4200 端口。
- 支持平台展示、公开链接解析、下载目录查看和打开下载文件夹。
- 仍可通过 `VIDEO_JIEXI_BASE_URL` 指向外部兼容服务，作为高级部署选项。

## 平台与能力范围

“支持平台”不等于所有平台拥有完全相同的数据字段。实际能力取决于平台登录状态、连接器和平台当前返回的数据。

| 平台 | 对标账号采集 | 自有作品复盘 | 说明 |
| --- | --- | --- | --- |
| 抖音 | 已接入并真实验证 | `douyin-mcp` 或官方文件导入 | 创作者字段只在实际返回时展示 |
| 小红书 | 已接入并真实验证 | OpenCLI 或官方文件导入 | 缺失字段保持为空 |
| Bilibili | 已接入并真实验证 | 暂未提供专用复盘页 | 支持账号与公开作品监控 |
| 快手 | 已接入并完成登录采集流程 | 暂未提供专用复盘页 | 登录状态可能影响采集 |

其他平台可以通过采集器适配器扩展，但 README 不把尚未真实验证的平台声明为开箱即用。

## 本地优先与可替换架构

工作台默认运行在本机：

- 前端：`http://127.0.0.1:5174`
- 主后端：`http://127.0.0.1:5409`
- OpenCLI Admin：`http://127.0.0.1:8031`（可选对标采集服务）
- video-jiexi：由 5409 后端在本机回环临时端口内置管理，不对用户暴露第二个固定端口

账号登录状态保留在对应平台连接器或本地浏览器环境中。API Key、运行时地址和本机路径写入本地配置，不应提交到 GitHub。

主工作台与采集器之间通过 HTTP 接口连接。缺少某个可选服务时，页面应明确显示不可用状态，而不是阻止整个项目启动。

## 快速开始

### Windows 本机使用

环境要求：

- Python 3.11+
- Node.js 18+

建议分层安装：先安装工作台核心；需要平台采集时再安装连接器，避免一次性下载所有大型组件。

```powershell
# 核心安装（后端、前端、内置视频解析）
.\scripts\setup-local.ps1

# 需要抖音/小红书对标采集时再安装连接器
.\scripts\install-connectors.ps1

# 检查端口、依赖、内置解析和本地占用空间
.\scripts\check-workbench.ps1
```

安装测试生成的 `.runtime\installer-smoke*` 可以安全清理；登录态、下载文件和工作数据不会被触碰：

```powershell
.\scripts\cleanup-workbench.ps1 -InstallerSmoke
```
- Google Chrome 或 Chromium
- PowerShell 7（推荐）

克隆项目：

```powershell
git clone https://github.com/usurikey91-ux/qianduan-video.git
cd qianduan-video
```

初始化本机环境（会在 Git 忽略的 `.runtime` 目录中自动安装固定版本的抖音连接器、OpenCLI、OpenCLI Admin 和视频解析运行时）：

```powershell
pwsh -File .\scripts\setup-local.ps1
```

启动工作台：

```powershell
pwsh -File .\scripts\workbench.ps1 start -OpenBrowser
```

查看运行状态：

```powershell
pwsh -File .\scripts\workbench.ps1 status
```

停止本轮启动的服务：

```powershell
pwsh -File .\scripts\workbench.ps1 stop
```

启动器会检查主后端、前端和已配置的可选服务，并把本轮进程信息保存在本地 `.runtime` 目录。

### 首次连接自己的平台账号

工作台启动后，在左侧进入“账号连接”：

1. 先确认本机已安装对应平台连接器。
2. 点击“扫码连接抖音”或“扫码连接小红书”。
3. 工作台会打开平台官方登录页，由账号本人扫码并完成验证码或安全校验。
4. 登录成功后核对页面显示的账号昵称，再进入“作品复盘”同步自己的后台数据。

工作台不提供账号密码输入框，也不会通过项目作者的服务器接收密码、验证码或 Cookie。每个人的登录态、数据库和配置只保留在自己的电脑上。

默认不需要另外克隆连接器。如果你已经有自己的连接器目录，也可以显式指定本机路径并跳过托管安装：

```powershell
pwsh -File .\scripts\setup-local.ps1 `
  -SkipConnectorInstall `
  -DouyinMcpProjectDir 'D:\path\to\douyin-mcp' `
  -OpenCliPath 'D:\path\to\opencli.cmd'
```

这些路径会写入 Git 忽略的 `runtime.local.json`。也可以手动复制 `runtime.local.example.json` 并填写 `douyinMcpProjectDir`、`douyinMcpCliPath` 和 `opencliPath`。自动安装使用 [connectors.lock.json](./connectors.lock.json) 固定上游版本，并应用仓库内经过验证的兼容补丁。

### 分别启动主工作台

后端：

```powershell
.\.venv\Scripts\python.exe .\sau_backend.py
```

前端：

```powershell
cd sau_frontend
npm.cmd install
npm.cmd run dev -- --host 127.0.0.1 --port 5174
```

如果 5174 已被其他项目占用，请先停止错误的 Vite 服务，不要把其他管理后台临时改到 5174 冒充本工作台。

## 可选服务配置

复制 `runtime.local.example.json` 为 `runtime.local.json`，可以配置辅助项目目录。也可以使用环境变量或 `settings.json` 指定服务地址。

常用环境变量：

```env
SAU_BACKEND_HOST=127.0.0.1
SAU_BACKEND_PORT=5409
# 默认只允许本机前端跨域；增加部署地址时用逗号分隔
SAU_ALLOWED_ORIGINS=http://127.0.0.1:5174,http://localhost:5174
# 仅在需要局域网/公网监听时启用，并同时设置管理员密码
SAU_AUTH_REQUIRED=0
SAU_ADMIN_USER=admin
SAU_ADMIN_PASSWORD=

OPENCLI_ADMIN_BASE_URL=http://127.0.0.1:8031/api/v1
OPENCLI_ADMIN_API_TOKEN=

# 留空即可使用内置解析引擎；仅在高级部署时填写外部兼容服务地址
VIDEO_JIEXI_BASE_URL=
VIDEO_JIEXI_API_TOKEN=

DOUYIN_MCP_PROJECT_DIR=D:\path\to\douyin-mcp
DOUYIN_MCP_CLI_PATH=
OPENCLI_PATH=
```

本机配置文件、Cookie、Token、数据库和运行时文件不应上传到公开仓库。

## 已知限制

- 平台登录状态、验证码和风控可能导致采集失败，需要在对应连接器中重新登录。
- 不同平台能取得的公开指标不同，不能保证字段完全一致。
- 样本不足或指标缺失时，系统不会为了给出结论而补造数据。
- 当前主要面向 Windows 本机个人使用；公网部署需要自行增加反向代理、鉴权和访问控制。
- B站和快手目前重点支持对标监控，尚未提供与抖音、小红书相同的自有作品复盘页。
- 项目当前不提供自动 AI 拆解和文案改写作为默认核心功能。
- 第三方平台页面或字段变化后，固定版本连接器仍可能需要更新；安装器不会绕过登录、验证码或平台风控。

## 项目方向

后续扩展应继续围绕“内容证据”而不是堆叠无关功能：

- 增加更多平台的稳定账号采集适配器。
- 丰富事实复盘中的趋势、分组和跨作品对比。
- 增加明确的数据质量、登录状态和采集失败提示。
- 让规则、平台字段和采集器保持可配置、可替换。
- 在不改变事实层的前提下，把 AI 保留为可选解释层，而不是数据来源。
